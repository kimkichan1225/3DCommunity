## 1. 프로젝트 개요

### 1.1 프로젝트 명
**메타 플라자 (Meta Plaza)** - 위치 기반 3D 소셜 메타버스 플랫폼

### 1.2 프로젝트 기간
2026년 1월 2일 ~ 2026년 1월 29일 (4주)

### 1.3 프로젝트 목표

| 구분 | 목표 | 상세 내용 |
|------|------|----------|
| 가 | 현실 기반 가상 공간 | Mapbox GPS 데이터와 Three.js 3D 렌더링의 정밀한 동기화 |
| 나 | 대규모 실시간성 | WebSocket(STOMP) 기반 다중 사용자 위치 및 채팅 동기화 (지연시간 100ms 이하) |
| 다 | 상용 수준 완성도 | 관리자 대시보드, 결제 시스템, 신고 처리 등 운영에 필요한 전반적 기능 구현 |
| 라 | 웹 접근성 극대화 | 설치 불필요, React 기반 고성능 3D 웹 애플리케이션 |
| 마 | 확장 가능한 생태계 | 게시판, 상점, 미니게임 등 다양한 모듈이 유기적으로 결합된 플랫폼 |

### 1.4 프로젝트 시나리오

#### 가) 배경 및 가정
- 별도의 클라이언트 설치 없이 웹 브라우저만으로 3D 게임 경험 제공
- 텍스트 기반 커뮤니티의 한계를 넘어, 실제 위치 기반의 즉각적 상호작용 니즈 증가

#### 나) 대상 사용자
| 사용자 유형 | 설명 |
|-------------|------|
| 일반 사용자 | 3D 아바타로 소통하고 게임을 즐기는 유저 |
| 커뮤니티 관리자 | 유저 활동을 모니터링하고 콘텐츠를 관리하는 운영자 |

#### 다) 사용자 시나리오
```
1. 접속 → 로그인 시 가상 광장(Public Square)에 스폰
2. 탐험 → WASD 키로 3D 공간을 이동하며 주변 유저와 마주침
3. 소통 → 반경 내 유저와 채팅하거나 친구를 맺고 DM을 주고받음
4. 게임 → 미니게임 로비에서 방을 만들거나 입장하여 다른 유저와 게임
5. 경제 → 상점에서 금화/은화로 아바타 아이템을 구매하고 착용
6. 공간 → GPS 기반으로 내 주변의 개인 룸을 탐색하고 방문
```

### 1.5 프로젝트 수행 요건

| 구분 | 요건 |
|------|------|
| 기술적 | React 19 + Three.js + Mapbox GL + Spring Boot 3.2 + PostgreSQL |
| 비즈니스적 | 실시간 위치 동기화, 권한별(관리자/유저) 격리, 토스페이먼츠 결제 연동 |
| 데이터 처리 | WebSocket 패킷 최적화, 대용량 3D 에셋(GLB) 비동기 로딩, 좌표 보간 처리 |

### 3.3 기술적 특징

#### 3.3.1 웹소켓 기반 실시간 양방향 통신 (STOMP over WebSockets)

**STOMP 프로토콜**
- HTTP와 달리 클라이언트와 서버가 연결을 유지한 채 데이터를 주고받는 메시징 프로토콜 구현
- `MultiplayerService`를 통해 0.1초 단위의 좌표 업데이트 브로드캐스트

**동적 구독 시스템**
```javascript
// 구독 경로 예시
/topic/minigame/rooms           // 전체 방 목록
/topic/minigame/room/{roomId}   // 특정 방 업데이트
/user/queue/game-invite         // 개인 초대 알림
/topic/chat/global              // 글로벌 채팅
```

#### 3.3.2 브라우저 기반 고성능 3D 물리 엔진 (React Three Fiber + Rapier)

**R3F 아키텍처**
- Three.js를 React 환경에 최적화된 선언적 컴포넌트 형태로 관리
- `useFrame` 훅을 통한 매 프레임 업데이트

**Wasm 기반 물리 연산**
- Rust로 작성된 Rapier 물리 엔진을 WebAssembly로 구동
- 브라우저 환경에서도 끊김 없는 충돌 감지와 중력 연산

```javascript
// 캐릭터 물리 설정
<RigidBody
  type="dynamic"
  colliders={false}
  mass={1}
  linearDamping={0.5}
  lockRotations={[true, false, true]} // Y축만 회전 허용
>
  <CapsuleCollider args={[2, 1.3]} position={[0, 3.2, 0]} />
</RigidBody>
```

**좌표 보간 (Interpolation)**
- 네트워크 레이턴시로 인한 캐릭터 끊김 방지
- 수신된 좌표 사이를 부드럽게 보간

#### 3.3.3 무상태(Stateless) JWT 보안 및 세션 관리

**JWT 인증**
- 서버에 세션을 저장하지 않는 Stateless 방식으로 확장성 확보
- Access Token 24시간 유효

**실시간 활성 유저 추적**
- `ActiveUserService`에서 메모리 기반 세션 맵 운영
- WebSocket 연결 끊김 시 즉시 접속자 목록에서 제거

**역할 기반 접근 제어**
```java
@PreAuthorize("hasRole('DEVELOPER')")
public ResponseEntity<?> adminOnlyEndpoint() { ... }
```

### ㄱㄱㅊ (Project Leader)

> Spring Boot와 WebSocket을 활용하여 Stateful한 게임 서버를 구축하는 과정이 매우 흥미로웠습니다. REST API의 Stateless한 특성과 WebSocket의 연결 지향적 특성을 조화롭게 아키텍처링하는 과정에서 많은 것을 배웠습니다.

### ㅈㅇㅂ (Project Assistant)

> 일반적인 웹 개발을 넘어 3D 그래픽스와 GIS(지리정보시스템)를 React에 녹여내는 작업은 큰 도전이었습니다. Mapbox GL과 Three.js의 좌표계가 다르기 때문에, 좌표 변환 문제를 수학적으로 해결해야 했습니다.

> 또한 3D 캔버스 위에 올라가는 UI는 기존 웹 UI와는 다른 접근이 필요했습니다. 게임 조작을 방해하지 않으면서도 필요한 정보를 직관적으로 전달하기 위해 'Phone UI' 컨셉을 도입했고, 사용성 테스트에서 좋은 반응을 얻어 만족스럽습니다.

### ㅇㅇㅎ (Project Assistant)

> Supabase의 다양한 기능을 활용한 안전하고 효율적인 시스템을 구축했습니다. PostgreSQL의 RLS(Row Level Security)를 통한 권한 관리와 실시간 동기화 구현이 도전적이면서 보람찬 작업이었습니다.
>
> 토스페이먼츠 결제 연동 과정에서 보안의 중요성을 다시 한번 깨달았습니다. 클라이언트에서 전달받은 금액을 그대로 신뢰하지 않고, 서버에서 패키지 정보를 조회하여 실제 금액과 대조하는 이중 검증 로직을 구현했습니다.
